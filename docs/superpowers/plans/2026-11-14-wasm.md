# WebAssembly (goifc-build.wasm, goifc-read.wasm) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship goifc's builders and IFC reader to the browser as two WebAssembly files that share one JSON contract, released with checksums and signed provenance.

**Architecture:** A pure-Go package `internal/wasmapi` owns the contract: it decodes requests, calls `geometry` and `ifc`, and encodes answers and GLBs. Two `js && wasm` main packages only move bytes across `syscall/js`. `wasm/goifc.js` runs each file in a Web Worker behind Promises. CI proves the wasm build gives the same bytes as Go; the Release workflow attaches the files to each tag.

**Tech Stack:** Go 1.25 (`GOOS=js GOARCH=wasm`), `encoding/json`, `syscall/js`, Node 24 for tests, GitHub Actions with `actions/attest-build-provenance`.

**Spec:** `docs/superpowers/specs/2026-11-14-wasm-design.md` (approved 2026-11-14).

## Global Constraints

- No new module dependency, test or not. `go.mod` stays as it is.
- Synthetic fixtures only. No customer, tenant, project or person names in any file. Grep the staged diff for private names before each commit, with the list kept outside the repo; it must print nothing.
- Signed Conventional Commits (`git commit -S`), never `--no-verify`, never WIP. End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `geometry` keeps building for `js/wasm`: no cgo, nothing OS-only.
- Every GitHub Action is pinned by full commit SHA with the version in a comment, as in the existing workflows.
- JSON field names are camelCase and come only from `wasmapi` DTO tags. No `geometry`, `model` or `ifc` type is passed to `json.Marshal` directly.
- A Go nil stays JSON `null`; a part not asked for is absent; nothing becomes 0 or `[]` by accident.
- Error codes, exactly: `too_wide`, `overlaps`, `above_wall`, `in_corner`, `layer_sliver`, `invalid_input`, `invalid_ifc`, `too_large`, `nothing_to_draw`; JS only: `worker_failed`.
- Caps: request ≤ 16 MiB (16,777,216 bytes) of JSON; ≤ 10,000 items (walls + rooms + slabs); IFC ≤ 256 MiB (268,435,456 bytes).
- Caller id pattern: `^[A-Za-z0-9_.:-]{1,64}$`, unique across the request.
- Size gate: `goifc-build.wasm` ≤ 1.2 MB (1,200,000 bytes) after `gzip -9`.
- Build flags for both files: `CGO_ENABLED=0 GOOS=js GOARCH=wasm go build -trimpath -ldflags="-s -w"`.

## Review Focus

1. **The same id on two kinds** (`walls[0].id == "a"` and `slabs[0].id == "a"`): `invalid_input` naming `a`, not two GLB nodes with one name. Test in Task 2.
2. **Trailing data after the request object** (`{...}{...}` or `{...} x`): `invalid_input`, not a build of the first object. Test in Task 2.
3. **`include` given but empty, or listing a part twice**: `invalid_input` naming the problem; only an omitted `include` means the default. Test in Task 3.
4. **A request with zero items**: `ok: true`, empty `walls` and `slabs` lists, a valid GLB with no meshes, and with `preview: true` a preview error `nothing_to_draw`. Test in Task 2.
5. **A refusal inside a layered room**: the error carries the room's `item`, the outline-edge `wall` index and the `opening` index, exactly as `PlacementError` reports them. Test in Task 2.

### Task 6: the wasm files, goifc.js and the CI gates

**Files:**
- Create: `cmd/goifc-build/main.go`, `cmd/goifc-read/main.go` (both `//go:build js && wasm`), `cmd/internal/jsbridge/bridge.go` (`//go:build js && wasm`; the shared copy-in/copy-out and version lookup), `wasm/goifc.js`, `wasm/test/goifc.test.mjs`, `wasm/test/shims.mjs`, `.github/scripts/wasm-size.sh`
- Create: `internal/wasmapi/memory_test.go`
- Modify: `Makefile` (target `wasm`), `.github/workflows/ci.yml` (`wasm` job), `.gitignore` (`dist/`)

**Interfaces:**
- Consumes: `wasmapi.Build`, `wasmapi.Read`.
- Produces:
  - Globals: `goifcBuild(request: string) → {answer: string, glb: Uint8Array|null}` and `goifcRead(ifc: Uint8Array, include: string[]|null) → {answer: string, glb: Uint8Array|null}`.
  - `jsbridge.Version() string` from `runtime/debug.ReadBuildInfo().Main.Version` (`(devel)` when empty).
  - `make wasm` → `dist/goifc-build.wasm`, `dist/goifc-read.wasm`, `dist/wasm_exec.js` (copied from `$(go env GOROOT)/lib/wasm/`), `dist/goifc.js`, `dist/goifc-contract.schema.json`.
  - `wasm/goifc.js` exports `createBuilder({ base })` → `{ build(request: object): Promise<{answer: object, glb: ArrayBuffer|null}>, close() }` and `createReader({ base })` → `{ read(bytes: Uint8Array|ArrayBuffer|Blob, { include }?): Promise<{answer, glb}>, close() }`. The same file is the worker script: it starts `new Worker(new URL(import.meta.url), { type: "module" })` and, inside a worker, runs the loop that imports `wasm_exec.js` from `base`, instantiates the `.wasm`, and answers messages. The GLB is posted as a transferred `ArrayBuffer`. `read` refuses a file over 268,435,456 bytes before posting it, with an `Error` whose `code` is `too_large`. If the worker dies (`error` event, or the Go program exits), the request in flight rejects with `code: "worker_failed"` and the queue continues on a fresh worker.

- [ ] **Step 1: Write the Node tests** in `wasm/test/goifc.test.mjs` (`node --test`). `shims.mjs` is test-only: a `Worker` over `worker_threads` and a `fetch` for `file:` URLs, installed on `globalThis` before importing `goifc.js`.
  - `parity`: for every `internal/wasmapi/testdata/build/*.request.json`, `build()` through `dist/` gives an answer whose bytes equal the golden after replacing the golden's `"goifcVersion":"v0.0.0-test"` with the built file's version, and a GLB equal to the golden `.glb`. Same for the read goldens.
  - `order`: three `build()` calls sent at once resolve in send order.
  - `too_large`: `read(new Uint8Array(268435457))` rejects with `code === "too_large"` and posts nothing to the worker.
  - `worker_failed`: a request that makes the worker exit (a test-only global the shim exposes to terminate the thread) rejects with `code === "worker_failed"`, and the next `build()` succeeds.
- [ ] **Step 2: Run** `make wasm && node --test wasm/test/` → FAIL (no `cmd` packages, no `goifc.js`).
- [ ] **Step 3: Implement** `cmd/`, `jsbridge`, `goifc.js`, the `wasm` Makefile target. The entry points hold no logic beyond `js.CopyBytesToGo`, the `wasmapi` call, `js.CopyBytesToJS` and `select {}`.

- [ ] **Step 5: Go-on-wasm parity.** Run the whole `wasmapi` suite compiled to wasm under Node, so every golden is also proven on wasm: `GOOS=js GOARCH=wasm go test -exec="$(go env GOROOT)/lib/wasm/go_js_wasm_exec" ./internal/wasmapi/` → PASS.
